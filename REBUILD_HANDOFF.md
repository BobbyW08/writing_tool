# Handoff for Claude Code: rebuild the data layer on Drizzle and Neon, remove Payload

Bobby's decision: the app is entirely a frontend. No admin, no logins, no Payload. Everything he built that matters moves with it: the ID codes, the metadata (tags, UNK and reviewNote, status, details rows, parent, aliases, gapPrompt, image), the Writing Studio, the in-place editing, the world tree, infobox and home hub. Record content does not block anything: he can re-enter it by hand. A one-time copy script (Part 6) is included as an option, and it runs only on his word.

Scope is strict. Do only what is written. If anything blocks you, log the exact error and stop that part. Do not improvise around a rule.

## Rules

1. Never print secrets. Do not echo `.env` or `.env.*`. Never write Bobby's login or any connection string into a file, script, log, report or commit.
2. Three databases exist. `DATABASE_URL` is the version 1 database: never touch it. `PAYLOAD_DATABASE_URL` is the current Payload database: read only, and only by the Part 6 copy script. `APP_DATABASE_URL` is the new database Bobby creates in Part 0: the only one this build writes to.
3. Bobby runs the dev server on port 3000. Do not start, restart or kill it. Do not use `Start-Process` or `taskkill`. Production timing runs use `next start` on port 3001 only.
4. PowerShell 5.1: use `Invoke-RestMethod`. Never name a helper `Del`, `Get`, `Post` or `Patch`.
5. No em dashes and no "--" in anything you write.
6. Hard rule 1: no AI anywhere in this build. Record text is never generated or rewritten.
7. No login and no auth code anywhere. Do not add middleware that blocks requests.
8. Mirror, do not redesign. The new tables carry the same fields with the same names and meanings as the current Payload collections (read `collections/*.ts`, `fields/*.ts`, `lib/codes.ts`, `lib/relationshipTypes.ts`, and every hook). Behavior that hooks provide today (code assignment, slug set once, tag and UNK handling, parent cycle check, conflict check on delete) must exist in the new data layer.
9. All reads and writes go through one data layer under `lib/db/`. Pages and server actions never build SQL inline. Select only the columns a view needs. The tree and list views use one light query, not one query per record.
10. `npm run build` must pass before every commit. The only commit authorized is the Part 1 safety commit, unless Bobby asks for more. Never commit `.env` files.

## Part 2: schema, code assignment, tags

1. New folder `db/`: `schema.ts`, `index.ts` (connection from `APP_DATABASE_URL`), `migrations/` generated by `drizzle-kit` and committed. Use a separate config file (for example `drizzle.app.config.ts`) so it cannot point at the version 1 database. Remove nothing from the version 1 setup yet.
2. Tables, mirroring the Payload collections: the world entries (characters, locations, items, cultures, factions, races, languages, lore; one table per type or one table with a type column, whichever lets the shared fields live once and each type keep its own fixed fields, and say which you chose and why in the report), `events`, `stories`, `writing` (with `canonState`), `relationships`, `tags`, `continuity` (schema only, unused until Phase 4), `media`, `counters`, and join tables for `involves`, tags and any other many-to-many.
3. Fields every entry shares: `code`, `slug`, `name`, `aliases`, `summary`, `status`, `gapPrompt`, `details` (rows with label, value, `inInfobox`), `body`, `parentId`, `imageId`, `tags`, `reviewNote`, and the origin fields (`sourceDocId`, `legacyId`). `body` and `writing.text` are stored as Markdown text, not JSON.
4. Codes: all current prefixes plus B, Y, M, P, H, D, N, A (reserved). A `counters` table with one row per prefix, created on first use, and code assignment done atomically in one statement or transaction, so ten parallel creates never collide. Counters never go backwards and codes are never reused. Keep the code pattern, `PREFIX_TO_SLUG` and the helpers in `lib/codes.ts`, now backed by the new tables.
5. Tags: `UNK` and `AI suggested` exist as built-in tags that cannot be deleted. `reviewNote` is a plain column. A helper `getUnkQueue()` returns every record tagged UNK across all tables, with its `reviewNote`.
6. Write `scripts/verify-db.ts`: apply the migration to a scratch schema or run against `APP_DATABASE_URL` with test rows tagged and deleted afterward, then prove: ten parallel creates in one prefix get ten distinct consecutive codes; a slug stays fixed after a rename; a parent cycle is refused; deleting a record that others point to is refused and lists them; counters after cleanup equal counters before; `getUnkQueue()` finds a tagged test record.
